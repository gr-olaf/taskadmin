# Техническое задание: TaskAdmin — Управление задачами

## 1. Общее описание

**Название системы:** TaskAdmin

**Назначение:** Веб-приложение для создания, хранения и просмотра задач, позволяющее пользователям систематизировать и организовывать рабочий процесс.

**Технологический стек:** HTML, CSS, JavaScript (frontend) + Node.js / Express (backend API) + PostgreSQL (база данных). Фронтенд использует **Bootstrap 5** (через CDN) для вёрстки и UI-компонентов.

**Запуск:**
- Локально: `npm start` / `npm run dev` — Express на порту 8080 раздаёт статику + API, БД — контейнер `my-postgres` (конфиг `.env`)
- Продакшен: `npm run start:prod` (или `NODE_ENV=production npm start`) — БД — PostgreSQL на Render.com (конфиг `.env.production`, SSL)

**Целевой пользователь:** Любой пользователь, нуждающийся в простом инструменте для управления списком задач в браузере.

## 3. Модель данных (PostgreSQL)

### Сущность: Task (Задача)

| Поле | Тип данных | Ограничения | Описание |
|------|-----------|-------------|----------|
| `id` | UUID | PK, `gen_random_uuid()` | Идентификатор задачи |
| `title` | TEXT | NOT NULL, 1–255 символов | Заголовок задачи |
| `description` | TEXT | NOT NULL, до 2000 символов | Описание задачи |
| `created_at` | TIMESTAMPTZ | NOT NULL, `now()` | Дата и время создания |
| `position` | INT | NOT NULL | Порядок сортировки (для DnD) |

**Хранение:** PostgreSQL, таблица `tasks`.
- Локально: PostgreSQL 18 (контейнер `my-postgres`), БД `taskadmin` (`.env`)
- Продакшен: PostgreSQL на Render.com, БД `taskadmindb_rbw2` (`.env.production`, SSL)

## 4. Детали интерфейса и реализации

### 4.1. Структура файлов

```
/
├── index.html          # Разметка страницы и формы (на Bootstrap)
├── css/style.css       # Дополнительные стили поверх Bootstrap (адаптивные)
├── js/app.js           # Логика фронтенда (рендер, валидация, fetch API)
├── server/
│   ├── app.js          # Express-приложение (API + статика, порт 8080)
│   ├── db.js           # Пул подключений к PostgreSQL + initDb()
│   └── routes/
│       └── tasks.js    # CRUD-эндпоинты + /reorder
├── .env                # Конфигурация подключения к БД для локального запуска (PGHOST и т.д.)
└── .env.production     # Конфигурация для продакшена (Render.com), не коммитится в git
```

**Выбор окружения:** `server/app.js` и `server/db.js` загружают `.env` по умолчанию (локально, без SSL) и `.env.production` при `NODE_ENV=production` (продакшен, с SSL `{ rejectUnauthorized: false }`). Подключение к БД приоритетно берётся из `DATABASE_URL` (автоматически подставляется Render для управляемого Postgres), иначе из `PGHOST`/`PGPORT`/`PGUSER`/`PGPASSWORD`/`PGDATABASE`.

### 4.2. API-эндпоинты

| Метод | Путь | Описание | Код |
|-------|------|----------|-----|
| `GET` | `/api/tasks` | Список задач (порядок: `position`, `created_at`) | 200 |
| `GET` | `/api/tasks/:id` | Одна задача по UUID | 200 / 404 |
| `POST` | `/api/tasks` | Создание задачи | 201 / 400 |
| `PUT` | `/api/tasks/:id` | Обновление задачи | 200 / 400 / 404 |
| `DELETE` | `/api/tasks/:id` | Удаление задачи | 204 / 404 |
| `PUT` | `/api/tasks/reorder` | Перемещение задач (порядок по массиву `ids`) | 200 / 400 |

- Язык текстов в интерфейсе — русский

### 4.6. Логика фронтенда (js/app.js)

Основные функции:

- `loadTasks()` — асинхронная загрузка задач через `GET /api/tasks`
- `renderTasks()` — отрисовка списка
- `showForm() / hideForm()` — управление формой
- `handleSubmit(event)` — валидация и отправка (POST / PUT)
- `createTask(title, description)` — `POST /api/tasks`
- `deleteTask(id)` — `DELETE /api/tasks/:id`
- `editTask(id)` — открытие формы с заполненными данными задачи для редактирования
- `updateTask(id, title, description)` — `PUT /api/tasks/:id`
- `reorderTasks(fromIndex, toIndex)` — перестановка в памяти + `PUT /api/tasks/reorder`
- `showError(message)` — вывод ошибки в баннере на странице
- Инициализация: асинхронная загрузка задач при старте, подписка на события `submit`, `click`, `dragstart`, `dragover`, `drop`

**Реализация Drag and Drop (FR-25–FR-29):**
- Используются нативные HTML5 события DnD (`dragstart`, `dragover`, `dragenter`, `dragleave`, `drop`, `dragend`)
- Элементу карточки присваивается `draggable="true"`
- При наведении на позицию вставки добавляется CSS-класс (например `.drag-over`) с визуальным индикатором
- По событию `drop` вычисляется целевой индекс и вызывается `reorderTasks()`, после чего список перерисовывается и порядок сохраняется на сервере через `PUT /api/tasks/reorder`

**Обработка валидации (FR-06):**
- Пустой заголовок → показать сообщение «Заголовок обязателен»
- Заголовок длиннее 255 символов → показать сообщение «Заголовок слишком длинный»
- Описание длиннее 2000 символов → показать сообщение
